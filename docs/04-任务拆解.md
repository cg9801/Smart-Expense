# 04 任务拆解（六周 · 可勾选）

> 投入：每周 > 24h（已确认）；单人开发；按"先跑通业务闭环，再加 AI 与压测"排序。
> 每个任务后面的 `→` 是**可验证的完成标准**，没通过不勾选。
> 变更（2026-10-26）：新增「AI 辅助审核」独立成第 5 周；原第 4 周拆分——发票链路留在第 4 周，压测/交付后移到第 6 周；JWT 鉴权由原定第 5 周提前到第 4 周（页面联调需要真实身份）。AI 与发票部分的完整设计见 [11-AI识别与辅助审核.md](11-AI识别与辅助审核.md)。

## 0. 技术决策（默认值，评审可改）

| 问题 | 默认决策 | 理由 |
|---|---|---|
| AI 接入方式 | **直接 HTTP 调多模态模型**，封装 `InvoiceRecognizer` 接口 | 不引入框架锁定，接口层可随时换 Spring AI；成本与超时可控 |
| 前端 | **Thymeleaf 3 个页面**（提交 / 待办 / 详情）+ 原生 fetch | 免 npm 工程与前端构建，半天上手；页面只有 3 个，Vue3 的收益仅界面观感 |
| 数据库迁移 | Docker 启动时挂载执行 `sql/schema.sql` + `sql/seed.sql` | 单机演示足够，Flyway 列为可选增强 |
| 鉴权 | JWT + Spring Security | 前后端分离与 JMeter 复用同一 token 流程 |
| 会签并发 | 数据库行锁（`SELECT ... FOR UPDATE`）+ 条件更新 | 量级小，先保证正确性；Redis Lua 作为压测后的优化项 |
| 公网演示 | 内网穿透（cpolar / Cloudflare Tunnel / frp），不买服务器 | 只暴露 8080 一个端口；免费版会断线，演示前预热 + 录屏兜底 |

**前端方案说明**：Thymeleaf 是 Spring 生态的服务端模板引擎——HTML 里用 `th:*` 绑定 Controller 放进 Model 的**服务端**数据，浏览器收到的是渲染好的页面；Vue3 是**浏览器端**框架，页面由 JS 在浏览器里渲染和更新，数据靠 `fetch` 调 REST 接口。两者不是替代关系：本项目接口本身是 REST，前端只是消费者，用 Thymeleaf 省掉 npm/构建/跨域，将来换成 Vue3 时后端不用改。

## 2. 第 2 周：审批流、并发、超时

| 天 | 任务 | 完成标准 |
|---|---|---|
| D1 | 待办列表（按 `deadline_at` 升序分页）、审批详情 | 待办只出现本人 `PENDING` 节点 |

## 5. 第 5 周：AI 辅助审核（只建议、不阻断）

| 天 | 任务 | 完成标准 |
|---|---|---|
| D1 | 硬规则引擎：`DUPLICATE_FILE_SUSPECT`、`DUPLICATE_INVOICE_SUSPECT`、金额不符、超预算 | 硬规则命中写 `hard_findings`，不阻断审批 |
| D1 | `ai_review` 建表 + 实体/Mapper + `uk_report_version` | 同一版本重跑幂等，只留一条 |
| D2 | `REPORT_SUBMITTED` 事件 + `ai-review-consumer`（复用 Outbox/MQ） | 提交后秒级产生建议记录，审批接口耗时不受影响 |
| D3 | 上下文组装（脱敏）+ prompt 定稿 + JSON Schema + `evidence` 白名单 | `evidence` 越界的 reason 被丢弃；非法 JSON 整条丢弃 |
| D4 | 风险合并规则（**只能升不能降**）+ 置信度阈值 + 失败降级 | 硬规则 `HIGH` 时 AI 输出 `LOW` 被覆盖 |
| D5 | 审批详情返回 `aiAdvice`；审批请求体带 `aiReviewId/aiAdopted`；审计落 `detail` | 一次请求只写一条审计；采纳率可统计 |
| D6 | 过期判定：`report_version` 比对 → `STALE` + 自动重算 | 撤回改单重提后，旧建议不再展示 |
| D7 | 故障注入：停模型服务、返回非法 JSON、超时 | 三种情况审批全链路正常，页面显示"暂无 AI 建议" |

**周末验收**：模型全程不可用时审批零影响；建议过期能自愈重算；`/admin/metrics` 能查到建议采纳率。

## 7. 完成定义（DoD）

- `mvn test` 全绿，状态机与幂等有专门用例；
- 关键路径有审计日志，任意单据可回放；
- 故障注入（消息丢失/重复、并发审批、**模型不可用/超时/非法 JSON**）有可复现脚本与截图；
- AI 建议有专门用例：非法 JSON、`evidence` 越界、版本过期、硬规则不降级；
- 模型服务全程不可用时，审批链路零影响（有停服复现记录）；
- 识别 P95、人工复核率、建议采纳率在 `/admin/metrics` 可查；
- 压测报告（JMeter 聚合报告）留档，对外说明与报告一致；
- README 能让陌生人 10 分钟内理解"做了什么、为什么这样设计、失败路径怎么处理"。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 审批链解析规则反复 | 返工 | 第 1 周先定死"缺级即失败"，把可配置化留到 v2 |
| Outbox 调度与业务事务边界写错 | 消息丢/重复 | 先写"同事务插入 outbox"的单测，再做投递 |
| 对账补偿改坏数据 | 一致性事故 | 补偿只走幂等接口（唯一键），先 dry-run 打印再执行 |
| 模型调用超时/费用 | 演示卡顿、账单失控 | `file_hash` 复用 + 单张总预算 + 每日调用上限；压测一律走 `MockRecognizer` |
| 模型幻觉导致误判 | 审批人被误导 | 风险只能升不能降 + `evidence` 白名单 + 建议不阻断 + 采纳留痕 |
| AI 建议过期 | 决策失真 | `report_version` 判定 `STALE` 并自动重算（`09` §5.6） |
| prompt injection（发票文本伪造指令） | 输出被劫持 | 声明"待分析数据" + 截断去控制字符 + JSON Schema 强约束 + `evidence` 白名单 |
| 识别失败被 MQ 放大重试 | 成本翻倍 | 识别失败**不 requeue**，MQ 只在消费异常时进死信（`09` §3.5） |
| 时间不足 | 交付缩水 | 发票识别是 v2：第 4 周前 3 天没跑通就砍成"人工录入 + 预留接口"；AI 审核是 v2.5，可整体后置 |

## 10. 已确认的决策

- **投入**：每周 > 24h → 调整为**六周**：第 4 周发票链路、第 5 周 AI 审核、第 6 周欠账补齐 + 复压 + 交付；不单设缓冲周，模型不可用时靠 `MockRecognizer` 离线兜底。
- **前端**：Thymeleaf 页面（提交 / 待办 / 详情 / 发票复核），不引入 npm 工程。
- **AI 边界**：AI 只出建议、不阻断、不自动通过；建议独立建表、风险只能升不能降、采纳写审计。
- **识别路线**：混合双实现 + `InvoiceRecognizer` 接口抽象——云 OCR 主、多模态备、压测走 Mock。
- **公网演示**：内网穿透（cpolar / Cloudflare Tunnel / frp），只暴露 8080，不暴露数据库与 MQ 端口；演示前预热，录屏兜底。

> 无剩余阻塞项：设计稿评审通过即可按第 1 周开工。
> 每个功能交付时按 [`AGENTS.md`](../AGENTS.md) §2 说明"职责 / 功能 / 对应文档 / 验证方式"。
