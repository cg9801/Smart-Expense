# 智能报销审批系统 — 交接与范围

> 本文件用于在新会话中无缝接手。读完这一页即可知道“为什么做、做什么、不做什么、怎么验收”。

## 1. 背景

- **动机**：常见的练习项目集中在电商/秒杀/优惠券，同质化严重，且大多是 Redis + 营销场景。
- **本次决策**：做一个**业务域完全不同**的项目，补“复杂业务状态机 + 数据一致性 + 外部服务集成”这条能力线。
- **定位**：个人兴趣开发的完整业务系统，目标是跑通真实财务流程，并能说清每一步失败路径。

## 2. 项目定位

**智能报销审批系统**：员工提交报销单 → 多级审批 → 预算扣减 → 生成付款单 → 对账；发票上传后异步识别金额/日期/发票号，低置信度转人工复核。

一句话卖点：**不是又一个商城/秒杀，而是把真实财务流程做对，并且能讲清失败路径。**

## 3. MVP 范围（必须做）

1. **报销单与状态机**
   - 状态：草稿 → 待审批 → 审批中 → 已通过 / 已驳回 → 已付款；支持撤回。
   - 状态流转表驱动，禁止非法流转；每次流转写审计日志。
2. **审批流**
   - 直属主管 → 财务 → 分管；支持会签 / 或签 / 转交。
   - **审批链快照**：提交时固化审批人与顺序，组织架构调整不影响在途单。
   - 超时提醒与自动升级。
3. **一致性与对账**
   - 审批通过 → 扣预算 → 生成付款单；Outbox 本地消息表 + RabbitMQ。
   - 消费端幂等；定时对账，差异可补偿。
4. **发票（v2，可后置）**
   - 上传 → 落库 → MQ 异步识别（云 OCR 主实现 + 多模态备实现 + `MockRecognizer`）→ JSON Schema 校验 → 规则校验（查重、超标、预算）→ 低置信度转人工。
   - 失败重试 + 死信；识别结果按 `file_hash` 复用，控制模型成本；识别结果**只预填表单**，用户确认后才写入单据。
5. **AI 辅助审核（v2.5，见 `docs/09-AI识别与辅助审核.md`）**
   - 提交后异步生成建议：硬规则（查重、金额不符、超预算）+ 模型语义嫌疑（类目与图像不符、连号/拆单）。
   - **只出建议、不阻断、不自动通过**；建议带 `report_version` 防过期，风险等级只能升不能降，采纳情况写审计。

**Out of scope（明确不做）**：微服务拆分、K8s、多租户、Flowable 全功能、复杂前端、真实支付对接。

## 4. 技术栈

| 层 | 选型 |
|---|---|
| 语言/框架 | Java 17、Spring Boot 3.x、MyBatis-Plus |
| 存储 | MySQL 8、Redis |
| 消息 | RabbitMQ |
| AI | 直接 HTTP 调云 OCR + 多模态模型，封装 `InvoiceRecognizer` 接口（不锁定框架，可换 Spring AI） |
| 文件 | MinIO（或本地磁盘，演示够用） |
| 文档/测试 | Knife4j、JUnit 5、JMeter |
| 部署 | Docker Compose |

## 5. 六个核心设计点（面试价值最高）

1. **审批链快照**：为什么快照？组织变更后在途单怎么办？
2. **幂等**：提交 token + 唯一索引；审批 `(approval_id, approver_id)` 唯一约束。
3. **并发**：会签多人同时审批用乐观锁；预算扣减用 Redis Lua 或数据库行锁。
4. **最终一致**：Outbox + MQ + 对账；故障注入验证消息丢失/重复消费。
5. **AI 只建议不决策**：结构化输出校验 + `evidence` 白名单、置信度阈值、风险只能升不能降、建议带 `report_version` 防过期、采纳率可统计、人工复核兜底、prompt injection 防护。
6. **可观测**：traceId、提交成功率、审批时长、识别 P95、对账差异数、审计追溯。

## 6. 六周计划

> 变更（2026-10-26）：新增 AI 辅助审核后由四周调整为六周，逐日任务见 [04-任务拆解.md](04-任务拆解.md)。

| 周 | 交付 | 验收 |
|---|---|---|
| 第 1 周 | 表结构、状态机、提交/撤回、幂等、审计日志 | 单测覆盖状态流转；重复提交只落一单 |
| 第 2 周 | 多级审批、预算冻结/释放/实扣、并发行锁 | 并发审批无重复扣预算 |
| 第 3 周 | MQ + Outbox + 付款单消费 + 对账（`run`） | 注入消息丢失/重复消费后可自愈 |
| 第 4 周 | JWT 鉴权、发票异步识别（云 OCR / 多模态 / Mock）、辅助填入、前端联调、Docker Compose | 停模型服务仍可走人工复核；同图二次上传不重复调模型 |
| 第 5 周 | AI 辅助审核：硬规则 + 建议、过期重算、采纳审计、故障注入 | 模型不可用时审批零影响；建议采纳率可查 |
| 第 6 周 | 转交/超时升级补齐、对账三接口、指标、JMeter 复压、README/演示、复盘 | 一条命令启动；3 分钟演示完整链路 |

## 7. 项目亮点表述（完成后）

对外介绍时按这个顺序讲：

> **智能报销审批系统（个人项目）**｜Spring Boot、MyBatis-Plus、MySQL、Redis、RabbitMQ、Spring AI
> - 设计报销单状态机与审批链快照，支持会签/或签/转交；提交时固化审批人，避免组织变更导致在途单卡死；幂等 token + 唯一索引解决重复提交，乐观锁处理并发审批。
> - 预算扣减与单据状态最终一致：Outbox 本地消息表 + RabbitMQ + 定时对账，消费端幂等；注入消息丢失/重复消费故障后，对账补偿使一致率恢复 100%。
> - 发票识别异步化：上传落库后投递 MQ，多模态模型按 JSON Schema 抽取金额/日期/发票号，置信度低于阈值转人工复核；失败重试 + 死信，主接口不被识别耗时阻塞。

**事实边界**：以上描述必须与已实现、已验证的功能一致；未实现的功能不要写进对外介绍。
