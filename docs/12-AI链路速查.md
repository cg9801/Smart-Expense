# 12 · AI 辅助审核链路速查

> 一页纸看懂：这个功能到底在干什么、代码在哪、还剩什么没做。
> 实现细节和取舍理由看 `docs/11-AI识别与辅助审核.md`；本文件只回答"它是什么、在哪、还差什么"。

## 1. 一句话说明

员工提交报销单后，系统**在后台自动**算一条"风险建议"（LOW / MEDIUM / HIGH + 理由），
审批人打开待办详情时能看到它，可以选择采纳或不采纳（采纳会写进审批审计）。

关键认知：**它不是对话框**。没有人在跟 AI 聊天，也没有"AI 帮你写报销单"。
它是"提交"这个动作的**副作用**，和发一条 MQ 消息、扣一次预算属于同类东西。

## 2. 五个环节（按数据流动顺序看）

| # | 环节 | 职责（只看这一列就够了） | 代码位置 |
|---|---|---|---|
| 1 | 提交时写事件 | 在批准提交的**同一个事务**里，往 outbox 插一条"已提交"消息 | `ReportServiceImpl.doSubmit` |
| 2 | 定时投递 | 每 2 秒扫 outbox，把消息投到 RabbitMQ | `OutboxRelay` |
| 3 | 消息消费 | 从队列取消息 → 消费幂等 → 调用 AI | `AiReviewConsumer` → `AiReviewService.consume` |
| 4 | Agent 循环 | 让模型最多问 5 次工具，最后吐一个 JSON 结论 | `AgentLoop` + `ai/tools/*` |
| 5 | 展示与采纳 | 详情接口带上建议；审批时记录采纳结果 | `ReportServiceImpl.getDetail` / `ApprovalServiceImpl` |

一条线背下来：

```
提交 → outbox_message → RabbitMQ → AiReviewConsumer → AgentLoop → ai_review 表 → 详情/审批
```

## 3. 只有两张表参与

| 表 | 作用 |
|---|---|
| `outbox_message` | 保证"提交成功"和"消息一定发出去"不会一个成一个败。AI 这条线只**读**它（消息已被别的消费者共用） |
| `ai_review` | 每条建议一行。`uk_report_version` 保证同一单据同一版本只算一次 |

## 4. 为什么要"循环"，而不是一次调用模型

因为模型不知道业务数据。一次调用只能这么问：

> "这是单据 JSON，你评一下风险。"

模型只能瞎编。Agent 循环改成：

> 第 1 次：模型说"给我看预算" → 系统执行 `getBudget` 查库 → 把结果塞回对话
> 第 2 次：模型说"给我看相似历史单" → 系统执行 `findSimilarReports` → 再塞回
> 第 3 次：模型说"我想清楚了，结论是 LOW" → 循环结束

**模型只负责"决定下一步看什么"和"下结论"，数据全部由本地代码查。**
这就是 Agent 和普通调用的区别，也是 `AgentLoop` 那 150 行的全部意义。

## 5. 五个工具（全是只读查询，不写库）

| 工具 | 查什么 |
|---|---|
| `getReportDetail` | 单据明细（金额、分类、摘要，最多 10 条） |
| `getBudget` | 部门当月预算余额（可用/已用/冻结） |
| `findSimilarReports` | 近 N 天相似历史单据的数量与均值 |
| `getInvoiceSummary` | 发票汇总（当前是占位，返回空数组） |
| `getPolicy` | 静态报销制度文本 |

## 10. 发票识别链路（2026-10-31 接入）

> 和 AI 审核是两条独立链路，共用 Outbox 但队列不同：识别看 `docs/11 §3`，切真模型看 `docs/18`。

```
上传发票 → invoice(PENDING) + outbox(INVOICE_UPLOADED) → se.invoice.recognize.queue
        → InvoiceRecognizeConsumer → InvoiceRecognitionService.consume
        → 抢占 PENDING→PROCESSING → InvoiceRecognizerChain(mock/qwen-vl) → 校验/阈值
        → 回写 SUCCESS / MANUAL / FAILED（条件更新，不覆盖人工复核）
```

| 环节 | 代码 |
|---|---|
| 上传 + 入队 | `InvoiceServiceImpl.upload` |
| 投递 | `OutboxRelay.routingKeyOf("INVOICE_UPLOADED")` |
| 消费 | `InvoiceRecognizeConsumer` → `InvoiceRecognitionServiceImpl` |
| 识别器 | `invoice/MockInvoiceRecognizer`、`invoice/QwenVlInvoiceRecognizer`、`InvoiceRecognizerChain` |
| 校验 | `InvoiceValidator`（金额/日期/号码） |
| 复核/重试 | `InvoiceServiceImpl.review/retry` + 前端 `/invoices` |
