## 7. 坑与注意事项（血泪版）

1. **pnpm + Windows junction**：默认隔离链接在 Windows 下不被 Node realpath，`vite` 内部 `import 'esbuild'` 会失败。已用 `frontend/pnpm-workspace.yaml` 的 `nodeLinker: hoisted` + `.npmrc` 的 `store-dir=.pnpm-store` 修复，勿改回。
2. **esbuild 子进程**：`vite build/dev` 需要 spawn 子进程，沙盒受限环境下会 `EPERM`；需要完整权限运行（本会话用 danger-full-access 后台 job）。
3. **PowerShell 5.1 不支持 `-Form`**：multipart 上传测试用 `curl.exe -F`，别在 `Invoke-RestMethod` 上死磕。
4. **集成测试依赖 seed 数据**：审批链第 2 级取"财务角色 id 最小者"。测试时若给李四（id=3）加 FINANCE 角色，`submit_creates_pending_report_with_three_step_chain` 的断言会从 `[张三,王五,赵六]` 漂移成 `[张三,李四,赵六]`——**验收后要还原李四角色**（已还原）。
5. **`aiAdvice.reasons` 是 JSON 数组字符串**（`"[]"`），前端渲染前必须 `JSON.parse`，否则 `v-for` 逐字符输出 `[` `]`（已修）。
6. **`timeline` 不含"创建草稿"**：`createDraft`/`updateDraft` 不写审计，草稿单轨迹为空属正常。
7. **Vite watcher 在 Windows 下 EBUSY 崩溃**：编辑器写文件会生成 `.xxx.tmpdir` 临时目录，chokidar 监听它时报 `EBUSY: resource busy or locked` 直接杀掉 dev server。已在 `vite.config.js` 的 `server.watch.ignored` 忽略 `**/*.tmpdir/**`、`**/.tmpdir/**`、`**/*.tmp`（并保留默认忽略项）；若仍出现，清掉 `frontend/src/**/.xxx.tmpdir` 后重启即可。
8. **dev server / 后端后台 job 偶发退出**：重跑 §2 命令即可，一般是 watcher/权限/环境回收，不是代码问题。
9. **中文乱码**：PowerShell 控制台输出 JSON 时中文显示乱码是编码问题，不影响接口与页面。
10. **`@TableLogic` 下的删除测试**：`selectById` 会自动过滤 `deleted=1`，想断言"行还在"要用 `JdbcTemplate` 直接查 `deleted` 列。
11. **JSON 列去重别用 LIKE**：MySQL 会把 JSON 规范化成 `{"k": 1}`（冒号后带空格），要用 `JSON_EXTRACT`。
12. **超时提醒去重的窗口**：同一节点 1 小时内只提醒一次，靠 `expense_status_log.action='TIMEOUT_REMIND'` + JSON 里的 `approvalId` 判断，别用"是否提醒过"布尔字段（表没有）。
13. **升级测试要按 seed 关系推**：技术部负责人=张三（原审批人）→ 会被排除，实际升级到上级部门负责人王五；写断言前先看 `seed.sql`。
14. **上传必须置 `PENDING`**：识别链路接入后，`InvoiceServiceImpl.upload` 若还沿用方案 A 的 `MANUAL`，发票永远不会被消费者处理（本会话踩过一次，测试立刻抓出来）。
15. **`mq_consume_log.msg_id` 只有 32 位**：测试里 `"msg-" + UUID` 是 40 位会直接 `Data too long`；用 UUID 去横线（32 位），生产就是 RabbitMQ 的 msgId。
16. **测试别和 MQ 消费者抢跑**：`InvoiceRecognitionTest` 用 `spring.rabbitmq.listener.simple.auto-startup=false` 关监听器，否则后台消费和断言竞态，状态时好时坏。
