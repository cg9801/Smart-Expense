| 项 | 原决策（04 §0） | 新决策（本稿） | 影响 |

**变更理由**：后端接口全部是 REST（`/api/v1/...`），前端只是消费者，换成 Vue3 后端零改动（04 §0 自己也写了这句话）。Vue3 页面数据由浏览器渲染、交互体验更好，也符合软件工程课程对前端框架的考察要求。

**两种落地形态（二选一，见 §1）**：不引入构建的 CDN 版 vs Vite 工程版。

## 1. 工程形态：两个方案对比（待确认）

| 维度 | 方案 A：CDN 免构建 | 方案 B：Vite 工程 |
|---|---|---|
| 目录 | `frontend/` 直接放 `.html`，双击或静态服务器打开 | `frontend/` 为独立 npm 工程（package.json / vite.config.js） |
| Vue3 引入 | `<script src="unpkg/vue@3">` 全局构建，无 SFC | npm 依赖，`.vue` 单文件组件 + HMR |
| CSS/HTML | 原生 `.css` 文件 + 原生 HTML，模板写在 HTML 里 | 同样可以只写原生 CSS，模板在 `.vue` 里 |
| 路由 | hash 路由手写（`#/reports/1`），约 30 行 | `vue-router`（history 模式，需后端/代理配合） |
| 请求 | 原生 `fetch` 封装 | `fetch` 或 axios |
| 启动 | 打开即用，联调时后端加 CORS 或前端走 `8080` 同源部署 | `npm run dev`（5173）+ Vite proxy 转发 `/api` 到 8080 |
| 上手成本 | 半小时 | 一晚上（要懂 node/npm） |
| 面试叙事 | "轻量选型、按场景克制引入工程化" | "标准工程化实践，组件化+HMR+proxy" |
| 风险 | 无组件化，页面多了模板会重复；CDN 断网即挂（可换本地 vue.global.js） | 依赖 npm 生态；与 04 §0 "免 npm" 决策冲突更大 |

**我的建议**：**方案 B（Vite 工程）**——课程作业要展示工程能力，且 5 个页面以上 SFC 组件化收益明显；开发期用 Vite proxy 解决跨域，演示期 `npm run build` 产物可挂进 Spring Boot `static/` 实现同源单端口部署（不破坏"只暴露 8080"的公网演示决策）。若栀麦不想要 node 环境，则选 A，功能完全一样。

## 12. 动效方案（2026-10-31）

### 12.1 设计原则
- **只动 `transform` / `opacity`**（外加少量 `filter`、`box-shadow`），不动 `width/height/top/left` 等布局属性，避免重排。
- **时长**：按钮 hover/回弹 280ms、按压反馈 80ms、ripple 550ms；环状图总时长 1000ms（段内 800ms + 120ms 错峰）；背景漂移 26s。
- **缓动**：弹簧感统一用 `cubic-bezier(.34, 1.56, .64, 1)`——首个控制点 1.56 让值越过终点产生 overshoot，末端 0.64 收得干净，形成"轻弹不浮夸"；环状图用 `easeOutCubic`（`1-(1-t)³`），起步快收尾稳。
- **可访问性**：`prefers-reduced-motion: reduce` 全关（背景漂移、按钮位移、环状图直接终态）；焦点态用 `:focus-visible` 保证键盘可见。

### 12.2 按钮（main.css `.btn` + App.vue ripple 委托）
| 状态 | 效果 | 参数 |
|---|---|---|
| 默认 | 180° 渐变（白→浅灰蓝）+ 顶部 1px 内高光 + 底部 2px 内阴影 + 外投影 | `linear-gradient(180deg,#fff,#f3f6fb)`；`inset 0 1px 0 rgba(255,255,255,.95)` + `inset 0 -2px 5px rgba(15,23,42,.05)` |
| hover | 上浮 1.5px、提亮 3%、阴影加深扩散 | `translateY(-1.5px)`、`brightness(1.03)`、`transition 280ms cubic-bezier(.34,1.56,.64,1)` |
| active | 下沉 1px + 缩放 0.96、内阴影加深 | `translateY(1px) scale(.96)`、`transition-duration 80ms`（按下要跟手，快进快出） |
| 释放 | 由默认 transition 曲线回弹，overshoot 产生弹簧感 | 回到 hover/base 时复用 280ms 弹簧曲线 |
| ripple | 从点击坐标扩散的柔光，径向白→透明 | JS 事件委托注入 `span.ripple`，尺寸 = 按钮长边×2，`550ms ease-out`，结束自动移除 |
| focus | 2px 主色外框 + 4px 间距 + 5px 柔光圈 | `outline: 2px solid var(--c-primary); outline-offset: 2px` |
| disabled | 降饱和 + 半透明，锁定位移 | `opacity:.5; filter:saturate(.25); transform:none` |

主按钮 `btn-primary` 用深蓝三段渐变（#3b82f6 → #2563eb → #1d4ed8）+ 白色顶部内高光；危险按钮同理（红三段）。

### 12.3 环状图（components/DonutChart.vue）
- **结构**：`<svg viewBox="0 0 200 200">`，圆心 (100,100)、半径 70、`stroke-width 22`、`pathLength="100"`（把周长归一成 100 个单位，百分比直接当长度用）。
- **渐进生长**：每段一个 `<circle>`，`rotate(起始角 - 90°)` 对齐自己的弧起点；`stroke-dasharray = "{pct × progress} {100 - pct × progress}"`，`progress` 由 `requestAnimationFrame` 驱动全局时间轴。
- **错峰**：第 i 段本地进度 = `clamp((t×1000 - i×120) / 800, 0, 1)`，配合 `easeOutCubic`——段与段之间错开 120ms，总时长仍 1000ms 内完成。
- **渐变描边 + 柔光**：每段独立 `linearGradient`（亮化 50% 色 → 本色）作为 `stroke`；`drop-shadow(0 0 8px {color}55)` 做柔和发光。
- **数字同步滚动**：中心数字 `displayed = total × easeOutCubic(t)`，与弧长同一时间轴，视觉上"弧在长、数字在滚"。
- **进入视口**：`IntersectionObserver`（threshold 0.3）触发，不在视口不跑动画。
- **完成脉冲**：中心数字 `scale 1 → 1.045 → 1`，`900ms cubic-bezier(.34,1.56,.64,1)` 只跑一次。
- **降级**：`prefers-reduced-motion` 或 `IntersectionObserver` 不可用时直接渲染终态。

### 12.4 背景层次（自下而上，`main.css` body / 伪元素）
| 层 | 元素 | 内容 | 参数 |
|---|---|---|---|
| 1 基础渐变 | `body` | 三层低饱和 radial（蓝 9% / 紫 7% / 绿 5%）+ 底部 linear（#f8fafc→#f2f6fc），`background-attachment: fixed` | 光晕 ≤13% 不透明度 |
| 2 细网格 | `body::before` | 34px 网格线（2.8% 黑），径向 mask 顶部渐隐 | 只影响视觉，不影响点击（`pointer-events:none`） |
| 3 漂移光斑 | `body::after` | 440px/380px 两团柔光，26s `ease-in-out` 交替漂移 | `translate3d + rotate 1.5deg + scale 1.04`，`will-change: transform` |
| 4 噪点 | `#app::before` | SVG `feTurbulence` 160px tile | 3.5% 不透明度，几乎不可见但消除纯色"塑料感" |

**对比度保障**：所有装饰层不透明度 ≤13%，正文 `#111827` 在 `#f8fafc` 上的对比度 >15:1（WCAG AAA），不干扰阅读。

## 13. 总预算池与双段调预算（2026-10-31）

### 13.1 设置总预算
- 新表 `budget_pool(period, total_amount)`（按月唯一，schema §2）：公司级总池，部门分配之和不得超过它。
- `GET /budgets/pool`：总池 / 已分配 / 未分配；`PUT /budgets/pool`（仅 ADMIN）：不得低于已分配（否则部门预算之和立刻超池）。
- 总览页新增「总预算池」卡片行：总池、已分配、未分配（负数标红）+「设置总预算」按钮 → 弹窗。
- `PUT /budgets/{deptId}` 增加超池校验：本部门新总额 + 其他部门已分配 ≤ 总预算，超了返回 409 并提示最多可分配额度。

### 13.2 分配预算：粗滑块 + 细对焦
- 调整弹窗重做：
  - 顶部对比「当前总额 / 新总额」；
  - **直接输入**：精确到分；
  - **粗调滑块**：`range`，范围 `0 ~ (总预算 − 其他部门已分配)`，步长 1000，轨道随拇指位置填充主色（`--fill` CSS 变量），拇指 spring 缩放；
